Дата: 25.09.2026. Статус: первый лабораторный срез выполнен; этап не закрыт до утверждения реального сценария и подключения выбранного ядра.

## 1. Что взято из готового проекта

Источник — предоставленный `agent-control-standard-integration.zip`, SHA-256
`BF87CB8EA31C7AB5CD2AF673C1AA41589E556BC715385C843FC0CE6AC35B6EAA`.
В `reference-implementations/agt/policy/lib/` проверены готовые модули:

- `approval.rego`: формирование решения `escalate` и списка согласующих;

- `ifc.rego`: решётка допусков и запрет потока в менее защищённый приёмник;

Microsoft Corporation. Сокращённые Rego-адаптации и лицензия сохранены в
`policy-gateway/third_party/agt/`. OPA на стенде отсутствует, поэтому Rego не
выдаётся за исполняемую защиту. Ограниченная исполняемая семантика перенесена в
`policy-gateway/l3/agt_controls.py`; различия записаны в реестре источников.

Дополнительно проверен `openai-agents-python-main.zip`, SHA-256
`0AFB8D6B6A1275613248A5508A18CC8A7082310900D596F9024DA4A3BD0655FE`.
Готовые `ToolInputGuardrail` и `ToolOutputGuardrail` лицензированы MIT, но
привязаны к `Agent`, `ToolContext`, `Runner` и `FunctionTool` OpenAI Agents SDK.
Input guardrail действительно располагается перед вызовом function tool;
output guardrail запускается после тела и не предотвращает уже совершённый
эффект. `reject_content` продолжает цикл модели, а `raise_exception` завершает
его — ни одно из них не заменяет наш трёхзначный шлюз и HITL. Поэтому код не
копировался: источник зарегистрирован как будущая точка адаптера только при
выборе этого SDK. Для shell/computer/custom tools нужны отдельные перехваты.

## 2. Что теперь исполняет профиль 0.4

| Контроль | Конфигурация | Решение до инструмента |
|---|---|---|
| Права инструмента | `tool_permissions` | Неизвестная задача/инструмент/операция → `deny` |
| Файловая граница | `workspace` | Путь вне workspace/неопределимый путь → `deny` |
| Оконный лимит | `rate_limits` | Превышение вызовов за окно → `deny` |
| Накопительный бюджет | `budgets` | Достигнуто число вызовов или время сеанса → `deny` |
| Память | разрешения `memory.read`/`memory.write` + namespace | Доступ только для явно указанных задач и префиксов ключей |
| Поток данных | `data_flow` | `class:protected` нельзя направить в приёмник `public`; неизвестная классификация считается `protected` |
| Внешний адресат | `egress` | `network.send` без адресата или вне allowlist → `deny` |
| HITL | `approval` + `critical_operations` | Точное действие → `require_review`; список согласующих возвращается хосту |
| Очередь HITL | `approval.max_outstanding_per_session` | Дубликат переиспользует pending ID; переполнение → `deny`; срок истёкших записей очищается |
| Целостность политики | `N05_POLICY_INTEGRITY` | `policy.modify` из инструментального контура → безусловный `deny` |
| Остановка | `session_stop` / `stop_session()` | Новые решения остановленного сеанса → `deny`; pending/grants удаляются |

Административный метод `approve()` остаётся имитацией отдельного доверенного
канала. Агент не может передать `approved: true`; токен одноразовый, ограничен
временем и связан с полным событием и хешем профиля.

## 3. Тумблеры и безопасное выключение

- выключение `tool_allowlist`, `workspace_boundary` или `data_flow` закрывает вызов;
- выключение `egress_allowlist` закрывает только сетевое действие;
- выключение `human_approval` запрещает критическое действие;
- выключение `budget_guard` отключает накопительный бюджет, но не оконный rate limit;
- `sandbox_mode: read-only` запрещает запись/удаление на уровне решения, но не создаёт ОС-песочницу.

## 4. Проверка

Полный прогон выполнен Python 3.13.2 из закреплённой лабораторной среды с
LangGraph 1.2.12:

- 65 Python-тестов: engine, L1, шесть AGT-derived L3-тестов, адаптер и реальный LangGraph runtime;
- 16 Node-тестов DSH-контракта;
- всего 81, ошибок 0, пропусков 0.

Новые отрицательные случаи: защищённые данные в public sink, неизвестный домен,
отсутствующий адресат, неизвестная классификация, исчерпание бюджета, неверный
согласующий, остановленный сеанс, аннулированное подтверждение и попытка `policy.modify`. Тестовые сетевые инструменты не выполняют
реальный сетевой запрос.

## 5. Что ещё не доказано

- DSH и его реальный `ToolRuntime` не запущены; LangGraph использует безвредные функции. В DSH статически подтверждены `Agent.cancel({kind: 'user'})`, `whenIdle()` и обязательный `AbortSignal`, но общий `stop_session()` ещё не вызывает их.
- Реальные категории данных, домены, инструменты и роли согласующих не утверждены.
- Счётчики токенов и стоимости не подключены: ядро пока не предоставляет доверенные значения.
- Состояние бюджетов/HITL находится в памяти и сбрасывается при перезапуске; долговечное хранилище планом не выбиралось.
- Файл YAML и административный канал не защищены ACL/ОС; этап 5 остаётся на паузе.
- L2 не реализован, песочница ОС и Firecracker не запускались.

Матрица тумблеров/автономности завершена в `Матрица_настроек_L3.md`.
Горячее изменение намеренно не
реализовано, поскольку оно сбросило бы in-memory бюджеты, stop-state и HITL.
Подключение жизненного цикла профиля и активной отмены DSH/LangGraph относится
к этапу 4 после выбора ядра.
