# Ревью этапов 1–3

Дата: 25.09.2026. Объект: лабораторная многоуровневая система безопасности
L1/L3, декларативный профиль, DSH/LangGraph-адаптеры и реестр происхождения.

## Итог

Архитектурное направление соответствует согласованной схеме: L1 маркирует
недоверенный вход, L3 детерминированно решает до инструмента, L2 остаётся `?`,
а ОС-изоляция не выдаётся за реализованную. После исправлений критических
дефектов, позволяющих обойти allowlist/HITL/data-flow в проверяемом лабораторном
контуре, не найдено. Это не аудит реального DSH, LLM или ОС.

## Исправлено в ходе ревью

### R1 — неограниченное состояние HITL — высокий приоритет

До ревью повторные критические запросы могли создавать неограниченные pending
и grants: бюджет учитывал разрешённые действия, но не запросы подтверждения.
Исправлено: одинаковый запрос переиспользует pending ID, изменённый запрос
заменяет прежний, просроченные записи удаляются, а
`approval.max_outstanding_per_session` ограничивает pending+grants. Добавлены
отрицательные тесты переполнения, дедупликации и замены аргументов.

### R2 — право на инструмент памяти означало право на всю память — средний приоритет

Ранее `memory.read/write` проверялись только по задаче и имени инструмента.
Исправлено: `memory.permissions` связывает задачу, инструмент и операцию с
каноническими префиксами ключей. Пустой ключ, абсолютная форма, `..`, обратный
слеш, чужой namespace и отключённый gate дают `deny`.

### R3 — устаревшие описания версии и числа тестов — средний приоритет

План и README продолжали говорить о пяти правилах и 56 тестах. Исправлено:
schema/policy/contract подняты до 0.4, описаны восемь ID и актуальный прогон.
Исторические суффиксы `v0.1` в именах двух файлов пока сохранены во избежание
поломки команд; версия определяется содержимым и SHA-256 профиля.

### R4 — второй запланированный open-source источник не был разобран — средний приоритет

Проверены `tool_guardrails.py`, `run_internal/tool_execution.py`, тесты и MIT
лицензия из `openai-agents-python-main.zip`. Решение: код не копировать.
Механизм полезен как будущий адаптер только для OpenAI Agents `FunctionTool`;
output guardrail срабатывает после тела и не предотвращает внешний эффект, а
shell/computer/custom tools идут другими путями.

## Остаточные риски и блокеры

| Приоритет | Ограничение | Почему не исправлено сейчас |
|---|---|---|
| Высокий | N04 запрещает новые решения, но не доказывает остановку уже начатого эффекта | Нужен выбранный runtime: в DSH это `Agent.cancel` + `AbortSignal` + `whenIdle`; произвольный инструмент может игнорировать кооперативную отмену |
| Высокий | Файл политики и административный канал не защищены от кода той же учётной записи | ACL/процесс/VM относятся к приостановленному этапу 5 и выбранной ОС |
| Средний | Состояние лимитов, stop и HITL находится в памяти одного процесса | Хранилище намеренно не выбиралось; горячая замена сбросила бы защитное состояние |
| Средний | Нет потокобезопасности для нескольких worker/process | Лабораторный worker последовательно читает stdin; эксплуатационная архитектура ядра неизвестна |
| Средний | `public/protected`, домены и namespace — тестовые | Реальные классы данных, инструменты и получатели не предоставлены командой |
| Средний | DSH и LangGraph не имеют подключённого реального L1 input hook | Выбор ядра и точка входа остаются `?` |
| Низкий | Commit предоставленных ZIP не установлен | Зафиксированы SHA-256 архивов и точные пути; commit нужен перед выпуском/публикацией |
| Низкий | Rego хранится как сокращённая адаптация и не исполняется | OPA не установлен; активна только явно протестированная Python-семантика |
| Процесс | Все файлы проекта пока `untracked` в Git | Нет надёжного baseline/diff; создание истории версий требует отдельного решения пользователя |

## Проверка после исправлений

- строгая загрузка YAML и compileall;
- 65 Python-тестов: Engine, L1, AGT-derived L3, LangGraph contract/runtime;
- 16 Node-тестов DSH adapter contract;
- всего 81 тест, 0 ошибок, 0 пропусков;
- реальных файловых/сетевых эффектов, LLM, DSH runtime и ОС-песочницы в тесте нет.

## Решение о переходе

Лабораторная часть этапа 3 пригодна как общий контракт и тестовый oracle.
Следующий этап — интеграция с выбранным ядром. До выбора допустимо готовить
только общие критерии приёмки; углубление одного адаптера или создание VM будет
отклонением от плана.
