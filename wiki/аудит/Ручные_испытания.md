# Как пользователь будет проверять методы в VM

Статус: проект руководства на согласование. [План](../../План_аудита_оригиналов_на_согласование.md) · [Карта](README.md). VM ещё не подготовлена; готовых команд запуска оригинальных методов пока нет.

Уточнение пользователя: агент не управляет VM или гостем; все действия в VirtualBox и команды опыта выполняет пользователь. Методички и отчёты оформляются по [учебному стандарту](Формат_лабораторной.md). Порядок: подготовка VM → методы без LLM → методы с детектором → отдельный опыт с локальной агентной моделью, если ресурсы позволяют.

## Один опыт — один наблюдаемый результат

1. На хосте открыть профиль отдельной лабораторной VM: проверить отсутствие общих папок, clipboard, drag-and-drop, USB и сети в режиме испытаний. Выбрать известный снимок.
2. В гостевой консоли открыть карточку метода и сверить ID версии, исходный файл и хеш. Оригинал не редактировать.
3. Создать отдельный run-id и искусственные данные в рабочем каталоге опыта. В карточке заранее указаны точные команды и ожидаемые результаты каждого шага.
4. Запустить оригинальный штатный тест. Сохранить команду, код выхода и вывод. Если тест не прошёл, остановить демонстрацию успешной защиты и записать причину.
5. Выполнить разрешённый пример. Проверить не только надпись `allow`, но и предусмотренный тестовый эффект, если метод управляет действием.
6. Выполнить запрещённый пример. Проверить решение и отсутствие запрещённого эффекта. Для детектора вместо «эффекта» проверить сигнал, а отдельно — реакцию вызывающего кода.
7. Если метод поддерживает HITL — отдельно ответить «отказать» и «подтвердить»; если поддерживает лимит/stop — довести до порога/остановки. Не требовать от helper функций, которых оригинал не предоставляет.
8. Открыть `run.md`, события и вывод. Записать фактическое наблюдение своими словами; приложить обезличенный скриншот при необходимости.
9. Остановить тест штатной командой; при зависании выключить только лабораторную VM. После сохранения разрешённых результатов восстановить чистый снимок для следующего независимого опыта.

## Формат инструкции каждого опыта

| Поле | Что пользователь должен увидеть |
|---|---|
| Место выполнения | ХОСТ или ГОСТЬ перед каждой командой |
| Предусловия | Снимок, пакет/версия, ресурсы, состояние сети |
| Команда | Полный проверенный вызов без догадок и скрытых подготовительных шагов |
| Вход | Небольшой искусственный пример и объяснение меняемого параметра |
| Ожидаемое | Точное решение/сообщение и ожидаемый эффект |
| Наблюдение | Что открыть: файл, stdout, окно подтверждения или лог |
| Ошибка | Как распознать проблему; когда прекратить опыт |
| Восстановление | Команда остановки и нужный снимок |
| Доказательство | run-id, версии, хеши, код выхода, фактический результат |

## Результат, который пойдёт в Git

Проверенная инструкция, небольшие искусственные входы, просмотренный протокол и ссылки на оригиналы. VM-диски, модели, окружения и сырые логи с чувствительными данными в Git не передаются. Для воспроизведения крупных компонентов сохраняются версии, контрольные суммы и инструкции получения.

Автоматический прогон дополняет ручной опыт. Статус «пользователь воспроизвёл» выставляется только после его фактического прохождения, а не после запуска помощником.
