## Что это за источник

README определяет проект как набор учебных **sandboxes, exploitation code и tutorials** для red teaming. Это не библиотека защитных политик для DSH/LangGraph. Часть стендов намеренно уязвима; эксплуатационные скрипты и команды установки из ZIP не являются инструкциями для нашего хоста. Найденные сценарии можно рассматривать как материал для будущих проверок при соблюдении профиля отдельной VM, но не как уже проверенный механизм защиты.

## Что пригодится нам позднее

1. Для A4 полезен принцип независимого доказательства: запрос → наблюдаемый ответ → решение защиты → реальный доступ/эффект. Эвристический ответ не подменяет проверку инструмента или файловой системы.
2. Проба на отравление памяти может стать отдельным **безопасным** сценарием с искусственными данными: две сессии, раздельные владельцы, наблюдение, попадает ли чужой факт в привилегированный контекст. Сам уязвимый стенд не переносить в проект.
3. Сценарий чтения/записи полезен для полноты L3: отдельно проверять оба направления и канонизацию пути. Описания конкретных эксплойтов в отчёт не копируются; запуск только на будущей разрешённой лабораторной стадии.
4. Формат отчётности `system_reconnaissance` полезен как образец: устойчивые ID проб, язык/категория, error/timeout отдельно от verdict, JSONL плюс читаемый Markdown. Его отчёты сохраняют сырые ответы — перед Git нужна проверка на секреты и обезличивание согласно плану.
