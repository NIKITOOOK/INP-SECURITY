# A1.4 — покрытие многоуровневой модели безопасности

Дата: 27.09.2026. Основание: [план 0.2](../../План_аудита_оригиналов_на_согласование.md), [схема и ЧТЗ](Матрица_требований_ЧТЗ_A1.1.md), [индекс 14 ZIP](Индекс_архивов_A1.3.md), [контроль QA](Контроль_A1_QA.md). Это **карта найденных оригиналов и пробелов**, а не проект новой архитектуры и не утверждение о работающей защите. Исследованы относящиеся к безопасности пути выборочно; отсутствие найденной реализации не означает доказанного отсутствия во всём ZIP.

## Как читать статусы

- **Реализация найдена:** в предоставленном ZIP статически прочитан конкретный исполняемый механизм и связанные тесты/конфигурация. Это **не** значит «испытан» или «подключён к нашему агенту».
- **Только описание/пример:** найдено объяснение или иллюстративный фрагмент, но не подтверждён завершённый применимый маршрут исполнения.
- **Не найдена в изученных путях:** просмотренные места не подтвердили этот точный метод; глобальное отсутствие не доказано.
- **Не проверено:** для данного блока недостаточно анализа или нет конечного ядра/среды для проверки эффекта.

Для **всех** строк ниже статус исполнения оригинала — **не запускался**, интеграция в агент команды — **не подтверждена**. Локальный `policy-gateway` из [A1.2](Сверка_заимствований_A1.2.md) остаётся объектом сравнения, а не доказательством работы upstream.

## L1 — входная защита и границы недоверенного текста

| Блок исходной схемы | Статус и найденный источник | Что не доказано / следующий опыт |
|---|---|---|
| Детекция prompt injection | **Реализация найдена только для отдельных поверхностей:** [NeMo](NeMo_A1.3.md) проверяет `user_message` на jailbreak; [Goose](Goose_A1.3.md) анализирует shell tool call с контекстом, по умолчанию выключен и переводит сигнал в approval. [OWASP](OWASP_CheatSheetSeries_A1.3.md) содержит ограниченный regex-пример. | Ни один из них не доказан как сквозная детекция *косвенной* инъекции из файлов, web, памяти и tool output. NeMo `injection_detection` — output rail по шаблонам кода/SQL/XSS, не этот блок. Ошибка детектора в локальном L1 даёт метки, не автоматический запрет. |
| Валидация входных данных | **Реализация найдена:** [Dify](Dify_A1.3.md) настраиваемо модерирует `inputs` и `query`; [NeMo](NeMo_A1.3.md) имеет input rails; [OWASP](OWASP_CheatSheetSeries_A1.3.md) даёт общие рекомендации. | Keyword-модерация и схема данных не равны защите от prompt injection. Не проверено прохождение всех поверхностей ввода до модели и отказ при ошибке валидатора. |
| Изоляция пользовательского/недоверенного ввода | **Частичная смежная реализация:** [Microsoft Agent Framework](Microsoft_Agent_Framework_A1.3.md) маркирует результаты функций, может скрыть их за ссылкой и использует отдельный `quarantined_llm`. [Hermes](Hermes_A1.3.md) разграничивает правила оператора и текст команды во вспомогательном approval-запросе. | Это не доказанная изоляция **каждого пользовательского ввода** нашего агента. При отсутствии quarantine client возможен placeholder; защита зависит от маршрута вызова. |
| Spotlighting — разделители (delimiting) | **Только описание/пример:** [OWASP](OWASP_CheatSheetSeries_A1.3.md) показывает текстовые метки в одной строке; [Hermes](Hermes_A1.3.md) — `<command>` во вспомогательном запросе. | Не найдена подтверждённая реализация Spotlighting для основного входа; метки сами по себе не препятствуют модели трактовать текст как инструкцию. |
| Spotlighting — маркировка (datamarking) | **Не найдена в изученных путях** как преобразование недоверенного текста именно по этому методу. Метки provenance в [Microsoft Agent Framework](Microsoft_Agent_Framework_A1.3.md) и локальном шлюзе — смежное управление данными. | Эквивалентность datamarking не подтверждена; нужен точный алгоритм и проверка того, что модель видит маркированный материал. |
| Spotlighting — кодирование (encoding) | **Не найдена в изученных путях** как защитное кодирование недоверенного ввода перед моделью. | Не подменять обычным JSON/URL-encoding или сериализацией аргументов; эффективность и обратное преобразование не проверены. |
| Prompt sandwiching | **Не найдена в изученных путях** как исполняемая схема «доверенная инструкция — недоверенный текст — повтор доверенной инструкции» для основного агента. [OWASP](OWASP_CheatSheetSeries_A1.3.md) даёт советы по структурированию prompt. | Не заявлять реализацию по наличию разделителей. Сначала нужен конкретный исходник и точка формирования сообщений, затем модельный опыт. |

|---|---|---|

Рассмотренные [AGT](AGT_A1.3.md) Rego-модули не подтверждают allowlist **имён инструментов**; его `egress.rego` относится к сетевым адресатам (строка «Коннекторы и сетевой шлюз» ниже). | Охват будущих/scoped инструментов, вложенных команд, отказа конфигурации и обходных путей различен. | Ограничение скорости/числа запросов | **Реализации найдены, но метрики разные:** [Dify](Dify_A1.3.md) ограничивает одновременные app requests через Redis; [Pydantic AI](Pydantic_AI_A1.3.md) считает вызовы инструментов в run; [AGT](AGT_A1.3.md) сравнивает бюджеты snapshot с лимитами. | Budget, concurrency и сетевой rate limit — разные механизмы. | Песочница (sandboxing) | **Реализации/точки подключения найдены:** [DSH](DSH_A1.3.md) — file fence и Linux/Windows/macOS runner; [OpenAI Agents](OpenAI_Agents_A1.3.md) — опциональный Docker backend; [Hermes](Hermes_A1.3.md) — опциональный Docker backend. ## Выбор первого пилота по критерию A1.4

**Выбран [AGT `budgets.rego` + `budgets_test.rego`](AGT_A1.3.md) для policy-level L3-пилота без LLM.** Оба оригинала и тесты находятся в ZIP, соответствуют нашей зоне декларативных политик и дают наглядные случаи «ниже порога / на пороге / malformed present / missing snapshot». Это не замена всему L3: budget-limit не является сетевым rate limiting и не доказывает запрет настоящего инструмента.

Ограничение выбора принципиально: в этом снимке `assemblePreToolCallSnapshot`/`assemblePostToolCallSnapshot` штатного Guardian создают нулевые budget counters, а `policy/lib/data.json` не задаёт budget-limit. Поэтому **не** брать обычный Guardian-demo как доказательство срабатывания лимита. На A2 подготовить неизменённые исходники/тесты, лицензию и отдельный внешний snapshot; на A4 пользователь в своей VM проверит оригинальный Rego/OPA verdict. Испытание связи policy decision с реальным tool execution — более поздняя отдельная работа, не часть этого первого пилота.

## Статус перехода

**A1.4 завершён как статическая матрица и отбор пилота; A1 завершён только как этап инвентаризации/аудита в рамках плана 0.2.** Пробелы сохранены: точные commit ID предоставленных ZIP не подтверждены, применимость лицензий к выбранным файлам требует отдельной проверки, оригиналы и тесты не запускались, методный coverage не исчерпывающий. [QA](Контроль_A1_QA.md) фиксирует 14/14 ZIP-хешей; 64 локальные ссылки существовали на момент независимой сверки пользователя, после добавления страницы A1.4 стало 65/65. Пользователь также сообщил о сверке 175 элементов внутри ZIP. Это не процент готовности ТЗ. Следующий возможный этап по плану — **A2.1**, но извлечение оригинала, зависимости и VM данным документом автоматически не начаты.
