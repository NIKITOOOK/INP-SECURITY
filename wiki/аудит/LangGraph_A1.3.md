## Исходные механизмы и границы

| Механизм | Наблюдение по исходнику и тестам | Значение для многоуровневой модели |
|---|---|---|
| `ToolNode(..., wrap_tool_call=..., awrap_tool_call=...)` | Обработчик получает `ToolCallRequest` и функцию `execute`; может проверить/изменить вызов **до** фактического `tool.invoke`/`ainvoke`, вернуть `ToolMessage` без исполнения или вызвать `execute` несколько раз. Синхронный и асинхронный пути реализованы отдельно. | Кандидат на точку L3 для детерминированного allow/deny, лимита или согласования. **Политика в LangGraph не задана**: она должна быть написана, обязательно подключена и испытана для каждого пути исполнения. Повторные вызовы `execute` опасны для инструментов с побочными эффектами. |
| Реестр инструментов `tools_by_name` | При отсутствии инструмента обычное исполнение возвращает ошибочный `ToolMessage`. Однако перехватчик получает запрос **до** этой проверки и может сам ответить за незарегистрированное имя; это подтверждено тестом. | Регистрация инструментов — не самостоятельная универсальная allowlist, если допускаются расширяющие перехватчики. В проектной политике имена, аргументы и возможность переадресации должны проверяться отдельно. |
| `handle_tool_errors` | Внутренние ошибки инструмента по умолчанию обрабатываются избирательно, но исключение из самого `wrap_tool_call` при включённой обработке превращается в `ToolMessage(status="error")`; при `False` пробрасывается. Тесты подтверждают оба случая. | Ошибка обработчика — не доказанный fail-stop графа. Для запрета надо проверять **реальный внешний эффект и дальнейший маршрут**; нельзя считать текст ошибки блокировкой всего запуска. |
| Несколько tool calls | `_func` передаёт вызовы в executor, `_afunc` использует асинхронное выполнение. | Без дополнительного ограничения вызовы могут исполняться конкурентно; «проверил один вызов» не означает атомарной политики для пачки и общего бюджета. |
| `interrupt(value)` / `Command(resume=...)` | `interrupt` останавливает узел и передаёт значение клиенту; для resume требуется checkpointer. При возобновлении узел **исполняется с начала**. Опциональная `response_schema` валидирует ответ только для Pydantic/TypedDict/dataclass; JSON Schema-словарь передаётся клиенту, но сам по себе не валидирует resume. | Механизм HITL, не готовое подтверждение личности человека и не политика разрешений. Побочные эффекты **перед** `interrupt` могут повториться. Проверку ответа, привязку к конкретному действию и учёт повторного исполнения делает интеграция. |
| `StateGraph.compile(checkpointer=...)`, `InMemorySaver` | `checkpointer=None` опционален для обычного графа; для `interrupt` нужен checkpointer и `thread_id`. `InMemorySaver` хранит состояние в памяти и самим исходником рекомендован только для отладки/тестов. | Checkpoint — средство возобновления, не L3-контроль и не песочница. Постоянная SQLite/БД сейчас не требуется; выбор долговечного хранилища относится к отдельному будущему решению, если оно понадобится для реального HITL после перезапуска. |

## Связь с нашим проектом, без нового внедрения

Локальный [граф](../../policy-gateway/langgraph_adapter/runtime.py) использует отдельный `policy_gate` и маршрутизацию к `ToolNode` только при `allow`; `approval_gate` использует `interrupt` и `InMemorySaver` для лабораторного прототипа. `ToolNode` создаётся **без** `wrap_tool_call`, поэтому этот upstream-перехват **не внедрён** в локальный граф. Адаптер и граф — собственный код на публичном API, не побайтовая копия LangGraph; текущий аудит не меняет их и не доказывает покрытие других мест вызова инструментов. Для текущего графа отдельно предусмотрено отклонение не-одиночного вызова, но сравнение с реальными побочными эффектами и проверка версии установленного wheel остаются открытыми.

LangGraph здесь — Python-оркестратор. Наличие этого ZIP не обеспечивает перенос того же кода в TypeScript DSH и не заменяет изоляцию Windows/Linux, Docker или VM. Эти границы нельзя объявить закрытыми на основании успешного `ToolNode` или checkpoint.
