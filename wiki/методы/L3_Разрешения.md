## Небольшой опыт в VM

Только **ГОСТЬ Ubuntu**, после [проверки условий](README.md#повторение-проверок). Модель не нужна: планировщик и инструменты лабораторные. Это инструкция повторения существующих тестов, не выполненная новая лабораторная.

1. В госте откройте каталог `policy-gateway` проверенной копии проекта и активируйте заранее подготовленное Python-окружение.
2. Прочитайте сценарии в [исходном тесте](../../policy-gateway/test_langgraph_end_to_end.py), затем запускайте по одному:

```bash
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_l3_denial_stops_before_toolnode
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_c02_unknown_tool_is_denied_before_toolnode
```

3. Сохраните команды, полный stdout/stderr и коды возврата отдельно для каждого случая. Заполните [протокол](README.md#протокол-одного-опыта).

**Ожидаемое по assertions теста:** Путь за пределами workspace даёт `P03_WORKSPACE_BOUNDARY`; неизвестный `send_email` — `P02_TOOL_ALLOWLIST`. Список вызовов лабораторного инструмента остаётся пустым. При успехе каждого запуска unittest выводит `OK`, код возврата 0; внутреннее решение проверяется assertions, но не обязательно печатается.

**Фактическое:** есть общий сохранённый отчёт прототипа; нового гостевого вывода этих двух команд пока нет. Не подставлять ожидаемое в фактическое.

## Ограничение и следующий шаг

Лабораторные read/delete не работают с реальными файлами. Тест не доказывает ОС-изоляцию, защиту от гонки проверки пути или невозможность обхода другим процессом.

Отдельно испытать реальные файловые операции в госте, включая ошибочные пути, после подготовки методики и изоляции.
