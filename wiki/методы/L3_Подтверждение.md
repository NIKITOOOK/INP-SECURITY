## Небольшой опыт в VM

Только **ГОСТЬ Ubuntu**, после [проверки условий](README.md#повторение-проверок). Модель не нужна: планировщик и инструменты лабораторные. Это инструкция повторения существующих тестов, не выполненная новая лабораторная.

1. В госте откройте каталог `policy-gateway` проверенной копии проекта и активируйте заранее подготовленное Python-окружение.
2. Прочитайте сценарии в [исходном тесте](../../policy-gateway/test_langgraph_end_to_end.py), затем запускайте по одному:

```bash
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_hitl_resume_preserves_l1_binding_and_executes_once
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_c08_resume_cannot_replace_approved_tool_arguments
```

3. Сохраните команды, полный stdout/stderr и коды возврата отдельно для каждого случая. Заполните [протокол](README.md#протокол-одного-опыта).

**Ожидаемое по assertions теста:** До подтверждения `require_review` и ноль вызовов; корректный resume исполняет лабораторный delete один раз. Подмена пути в resume даёт `INVALID_APPROVAL_RESPONSE` и ноль вызовов. При успехе каждого запуска unittest выводит `OK`, код возврата 0; внутреннее решение проверяется assertions, но не обязательно печатается.

**Фактическое:** есть общий сохранённый отчёт прототипа; нового гостевого вывода этих двух команд пока нет. Не подставлять ожидаемое в фактическое.

## Ограничение и следующий шаг

Подтверждение подаётся тестом, пользовательский интерфейс и аутентификация согласующего не реализованы. Лабораторный delete не удаляет файл.

Проверить доверенный канал подтверждения и реальное действие отдельно; не считать один verdict фактической остановкой внешнего инструмента.
