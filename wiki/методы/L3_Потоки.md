## Небольшой опыт в VM

Только **ГОСТЬ Ubuntu**, после [проверки условий](README.md#повторение-проверок). Модель не нужна: планировщик и инструменты лабораторные. Это инструкция повторения существующих тестов, не выполненная новая лабораторная.

1. В госте откройте каталог `policy-gateway` проверенной копии проекта и активируйте заранее подготовленное Python-окружение.
2. Прочитайте сценарии в [исходном тесте](../../policy-gateway/test_langgraph_end_to_end.py), затем запускайте по одному:

```bash
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_c05_protected_input_cannot_reach_public_network_sink
python -m unittest -v test_langgraph_end_to_end.LangGraphEndToEndTests.test_c06_public_input_still_cannot_use_off_list_domain
```

3. Сохраните команды, полный stdout/stderr и коды возврата отдельно для каждого случая. Заполните [протокол](README.md#протокол-одного-опыта).

**Ожидаемое по assertions теста:** Защищённый вход даёт `ifc_clearance_violation`; публичный вход с адресатом вне списка — `egress_destination_not_allowed`. Реальный HTTP-запрос в этих тестах не отправляется. При успехе каждого запуска unittest выводит `OK`, код возврата 0; внутреннее решение проверяется assertions, но не обязательно печатается.

**Фактическое:** есть общий сохранённый отчёт прототипа; нового гостевого вывода этих двух команд пока нет. Не подставлять ожидаемое в фактическое.

## Ограничение и следующий шаг

Прикладная проверка не является firewall всех процессов. Не доказаны полнота аннотаций, защита от перенаправлений и реальная блокировка сетевого пакета.

Подготовить отдельный опыт с контролируемым получателем внутри изолированной сети VM и наблюдением фактического трафика.
