Контракт событий и политик L1/L3 — черновик 0.4

Дата: 24.09.2026. Область: исследовательский прототип многоуровневой защиты агента. Основание: схема ядра агента, предоставленная пользователем, и статический просмотр DeepSeek Harness 0.1.7-rc.1 из локального ZIP с SHA-256 7DDDFDB7A5E25001394B895A9EEA743C89DF9238BB0093EFF34CB5ABD1C4417E.

1. Граница первой итерации

Компоненты ядра публикуют сведения о вводе, предложенных действиях и результатах во внутреннюю шину. L1 анализирует входные данные и добавляет метки. L3 проверяет полномочия перед действием. L2 остаётся в контракте как возможный потребитель меток, но в первом профиле выключен. Схема дополняется позднее; приведённый набор событий не претендует на полноту.

интерпретатор / LLM / память / инструменты
             │
             ▼
       внутренняя шина
        │          │
        ▼          ▼
   L1: метки    L3: решение перед исполнением
        │          │
        └────┬─────┘
             ▼
       журнал решений

Шина имеет два разных механизма:

  • Уведомление (emit): сообщает о полученном вводе и завершённом действии; слушатель не способен задержать уже совершённый эффект.
  • Запрос решения (gate): ожидает ответ до вызова инструмента. Ошибка, отсутствие обработчика или некорректное решение дают deny для защищённого действия.

Это различие обязательно: запись tool/call или session/event в журнал не является разрешением на исполнение.

2. Минимальный конверт события

Поле Смысл
event_id, timestamp Уникальность и порядок событий
session_id, task_id, actor_id Контекст пользователя и задачи; неизвестное значение не даёт привилегий
kind Тип события из версии словаря
origin user, model, tool, web, file, memory или system
trust trusted, untrusted, unknown; внешние результаты по умолчанию untrusted
labels Например prompt_injection_suspected, secret, personal
payload_ref Ссылка на содержимое; в журнале решений хранится хеш/краткое описание, а не секретный текст
causation_id, call_id Связь входа с предлагаемым вызовом и результатом
source_event_ids Входные события, которые доверенный конвейер связал с вызовом; модель не задаёт это поле
data_labels Объединённые метки связанных входов; отсутствие надёжной связи даёт unknown и untrusted
policy_version Неизменяемая версия правил, применённая к данному решению

Первый словарь событий: input.received, input.checked, tool.requested, tool.decided, tool.completed, memory.write.requested. Последнее зарезервировано для следующего этапа и пока не реализуется. Для tool.requested дополнительно нужны канонические tool_name, operation, arguments, resource, source_event_ids, data_labels. Проверка выполняется по окончательным аргументам непосредственно перед исполнением. В лабораторном конвейере L1Pipeline хранит результат input.checked и сам формирует два поля происхождения; попытка передать их в исходном запросе инструмента отклоняется.

3. Решения и порядок применения

На вход L3 поступают событие tool.requested, метки L1 и снимок активной конфигурации. На выходе: allow, deny или require_review с rule_id и причиной. sanitize относится к обработке данных L1, а не к разрешению инструмента: DSH запрещает менять аргументы уже зарегистрированного вызова в tools/pre-execute.

При одновременном срабатывании правил приоритет: deny выше require_review, require_review выше allow. Отсутствие подходящего разрешения означает deny. Одобрение человека действует только на конкретный call_id и хеш окончательных аргументов; если они изменились, требуется новая проверка.

Отключение проверки может существовать в исследовательском профиле для сравнения результатов, но не должно превращать отсутствие проверки в allow на исполняющем контуре. Профиль выбирает оператор вне процесса агента; модель не меняет его. Версия профиля фиксируется для сеанса. Вопрос о горячем обновлении остаётся открытым до проектирования контрольной плоскости.

4. Исполняемые правила лабораторного профиля

ID Вход / условие Результат Назначение
P01_INPUT_PROVENANCE input.received из web, file, tool или memory без проверенного доверия L1 ставит untrusted; детектор может добавить prompt_injection_suspected Не считать внешний текст распоряжением
P02_TOOL_ALLOWLIST tool.requested: инструмент или операция отсутствует в разрешённом наборе задачи deny Запрет по умолчанию
P03_WORKSPACE_BOUNDARY Чтение/запись/удаление в путь вне канонического workspace либо путь нельзя разрешить deny Ограничить доступ к файлам
P04_RATE_LIMIT Счётчик вызовов инструмента за окно превышает лимит deny с retry_after Ограничить скорость/число запросов
P05_CRITICAL_APPROVAL Удаление, отправка данных во внешнюю службу или изменение политики require_review; после одноразового одобрения — allow, при недоступности канала — deny HITL для опасного действия
N03_DATA_FLOW Класс данных выше допуска получателя либо адресат сетевого действия отсутствует в allowlist deny до HITL Не допустить передачи protected в public-приёмник и отправки неизвестному адресу
N04_STOP Доверенный управляющий контур остановил session_id deny для всех новых решений; ожидающие подтверждения и grants аннулируются После команды остановки не выдавать новые разрешения
N05_POLICY_INTEGRITY Инструмент модели предлагает policy.modify безусловный deny Отделить администрирование политики от инструментов агента

prompt_injection_suspected является сигналом L1, а не доказательством атаки. L3 не разрешает утечку или опасное действие лишь потому, что детектор не нашёл инъекцию. Поток данных проверяется отдельно: лабораторные метки class:public и class:protected сравниваются с допуском инструмента; при отсутствии классификации применяется консервативное protected. Это испытательная классификация, а не утверждённые категории корпоративных данных.

5. Связь с DeepSeek Harness

Потребность проекта Найденная точка DSH Ограничение
Решение до запуска инструмента packages/core/tools/src/index.ts: tools/pre-execute, PreToolDecision Возвращает allow, deny, cancel, ask; аргументы уже зарегистрированы и не переписываются
Одобрение человека docs/subsystems/approval.md, ctx.approval.request allowed-once — единственное положительное решение; отказ и недоступность закрывают вызов
Проверка результата tools/post-execute Может блокировать/заменять результат для модели, но не отменяет уже сделанное внешнее действие
Аудит и восстановление docs/subsystems/session.md, tool/call/tool/result; docs/subsystems/persistence.md Записи журнала не являются предисполнительным шлюзом
Файловая песочница docs/subsystems/sandbox.md, ctx.sandboxPolicy Режимы ограничивают файловые эффекты; сеть и видимость процессов за их пределами
Конфигурация docs/subsystems/settings.md, docs/subsystems/permission-presets.md Переключатели DSH надо сопоставить с профилями проекта; права на изменение конфигурации ещё требуется определить

Для первой интеграции вероятен отдельный DSH-плагин, подписанный на tools/pre-execute и tools/post-execute. Точку перехвата пользовательского ввода L1 нужно подтвердить отдельным статическим обзором; пока это наш проектный контракт, а не обнаруженный готовый API DSH.

6. Проверка на синтетических событиях

Тест Событие Ожидаемый результат
T01 Веб-страница содержит «игнорируй инструкции» untrusted, prompt_injection_suspected; сам по себе текст не вызывает инструмент
T02 Неизвестный инструмент send_email в задаче чтения deny, P02_TOOL_ALLOWLIST
T03 Запись за пределы workspace через .. или ссылку deny, P03_WORKSPACE_BOUNDARY
T04 Шестой вызов при лимите пять за минуту deny, P04_RATE_LIMIT
T05 Разрешённый инструмент запрашивает удаление require_review, P05_CRITICAL_APPROVAL; без ответа — deny
T06 class:protected направляется через public network sink либо домен отсутствует в allowlist deny, N03_DATA_FLOW
T07 Аргументы удаления меняются после подтверждения прежний токен недействителен; требуется новое подтверждение
T08 Достигнут накопительный бюджет либо переполнена очередь HITL deny до тела инструмента
T09 Доверенный контур останавливает сеанс новые решения deny, pending/grants аннулированы
T10 Агент предлагает policy.modify или профиль не проходит схему deny либо отказ загрузки

Реализованы Python-симулятор policy-gateway/engine.py, строгая проверка YAML и policy-gateway/l1/pipeline.py. Метки L1 связываются с конкретным запросом L3 на лабораторном конвейере; неизвестная связь остаётся unknown/untrusted. На L3 добавлены накопительный бюджет сеанса, права памяти, решётка потоков данных, allowlist сетевых получателей, доверенная остановка выдачи новых разрешений и запрет policy.modify. Семантика budget/approval/egress/IFC ограниченно адаптирована из MIT-модулей AGT; OPA не установлен, а сохранённые Rego-файлы сами по себе не исполняются. stop_session() реализует контрольную плоскость шлюза и аннулирование HITL-состояния; отмена уже запущенного действия требует API выбранного ядра. В DSH найдены Agent.cancel(...), whenIdle() и обязательный AbortSignal инструмента, но они ещё не подключены к адаптеру. Добавлен адаптированный клиент локального NeMo Guardrails detector endpoint (l1/nemo_jailbreak.py, Apache-2.0), но сам классификатор/модель не установлен и не запускался. DSH- и LangGraph-адаптеры пока не имеют реального входного hook и поэтому передают unknown/untrusted; консервативная классификация стенда для такого случая — protected. Текущий стенд не доказывает распространение меток в настоящем ядре и не проверяет изоляцию ОС.

7. Открытые решения

  1. Какие события ввода и памяти реально доступны через расширения DSH; лабораторный L1Pipeline готов, но его нужно подключить к настоящему входному hook.
  2. Как хранить и защищать настройки: путь, ACL, владелец и разрешённый механизм изменения.
  3. Какие действия считать критическими для HITL в демонстрационном сценарии.
  4. Какой лимит частоты выбрать и считать ли его по пользователю, задаче или инструменту.
  5. Какой экспериментальный профиль изоляции ОС использовать при запуске DSH в VirtualBox.

8. Происхождение и ограничения

Наименования tools/pre-execute, tools/post-execute, approval.request, sandboxPolicy и виды решений взяты из указанной выше локальной копии DSH; остальные имена событий и правила P01–P05 — предлагаемая спецификация проекта. Клиент NeMo в policy-gateway/l1/nemo_jailbreak.py адаптирован из nemoguardrails/library/jailbreak_detection/request.py; уведомление и лицензия находятся в policy-gateway/third_party/NEMO_GUARDRAILS_NOTICE.md. Точный commit исходных ZIP остаётся неподтверждённым.
