AGT budgets — отчёт пилотного сеанса 29.09.2026

Статус: частично выполненный локальный пилот. Записано по подтверждённым выводам консоли в этом чате; полные исходные журналы остаются внутри VM. Формальная приёмка всей A3 и редакции плана 0.3 не заявляется. Остальные архивы этим сеансом не испытаны.

Цель

Проверить политику L3 ограничения счётчиков бюджета: штатные Rego-тесты, четыре входа и обработку решений в выбранных тестах оригинальной ACS-интеграции. Проверка фактической остановки реального инструмента остаётся отдельным шагом.

Фактический ход

  1. После ошибки Permission denied для OPA добавлено право исполнения пользователю; подтверждены версия и хеш.
  2. Выполнены оригинальные budgets.rego и budgets_test.rego через opa test --fail-on-empty -v: 16/16 passed, exit 0.
  3. Выполнены четыре opa eval с запросом data.agt.budgets.deny_if_budget_exceeded(input.thresholds); все команды завершились с exit 0.
  4. Наша учебная Python-симуляция сравнила два обработчика отсутствующего deny. ACTION_EXECUTED/ACTION_BLOCKED были только печатными маркерами, не исполнением инструментов. Это не оригинальная интеграция.
  5. Пользователь временно включил NAT для снабжения. Bun загружен только в VM; зависимости установлены через bun install --frozen-lockfile --ignore-scripts --no-progress: exit 0, 82 packages; bun.lock не изменился. Во время этого снабжения оригинальные тесты не запускались.
  6. Пользователь отключил виртуальный кабель. Перед тестами подтверждены enp0s3 DOWN/NO-CARRIER, отсутствие маршрутов IPv4/IPv6 (Network is unreachable), ошибка DNS HTTPS-запроса к registry.npmjs.org (exit 6). Адаптер остаётся настроенным как NAT; абсолютная безопасность гипервизора не доказана.
  7. В каталоге AGT выполнено:
timeout 90s /home/labuser/tools/bun-1.3.14/bun test --timeout 10000 ./packages/guardian/test/map-verdict.test.ts ./packages/host-adapter/test/govern-step.test.ts

Результат: 77 pass, 0 fail, 165 expect calls; 2 файла, exit 0. Проверена оригинальная логика обработчиков; govern-step использует mock Guardian. Полная цепочка SDK → OPA → реальный инструмент этим не проверена. 8. В VM записаны CONTINUE-HERE.md и архив session-evidence-20260929.tar.gz с контрольной суммой. gzip -t и sha256sum -c завершились успешно. Значение SHA-256 архива в этот отчёт не перенесено.

Вывод и контрольные вопросы

  • Что делает OPA? Вычисляет решение Rego по входу и данным; само вычисление verdict не доказывает прекращение действия инструментом.
  • Где проходит порог? В испытанном случае счётчик, равный лимиту 5, вызывает deny.
  • Как обработан плохой счётчик? Присутствующий нечисловой счётчик дал budget_counter_invalid.
  • Что означает отсутствующий snapshot? Helper не выдал verdict; доверенный обработчик должен отдельно определить поведение.
  • Что подтвердили 77 тестов? Выбранную логику отображения verdict и governStep с mock Guardian, не полноценную интеграцию с настоящим OPA/инструментом.
  • Что ещё не доказано? Фактический enforcement, получение реальных счётчиков, полнота пороговой конфигурации и устойчивость полной цепочки к отказам.

По статическому чтению zeroedBudgets() задаёт нулевые счётчики, штатный policy/lib/data.json не содержит budget thresholds, а вызов helper в agt_default.rego зависит от наличия cfg.budgets. Это направления следующей проверки, не доказанная уязвимость.

Продолжение и завершение

  1. Пользователь открывает проект на D:; другой чат читает AGENTS.md, ПЕРЕДАЧА.md и этот отчёт.
  2. До нового запуска сверить снимок/состояние VM, изоляцию и сохранившиеся журналы. Перед каждым вводом объяснять проверку и ожидаемый эффект, предупреждать и оставлять возможность прервать.
  3. Следующий блок пилота: реальные Guardian/SDK/OPA и связь verdict с эффектом; затем счётчики, thresholds и отказные случаи. Объяснять каждую проверку заранее. Это не разрешение сразу запускать все 14 архивов.
  4. Экспортировать архив журналов на D: и сверить гостевой/хостовый SHA-256; дополнить этот отчёт доказательствами.
  5. Штатное выключение и новый снимок выполняет пользователь. По скриншоту пользователя 29.09 выключение и наличие снимка agt-prepared-results-20260929 подтверждены; восстановление и содержимое снимка не проверялись. Текущее состояние Azure повторно не проверено.
