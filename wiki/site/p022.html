Симулятор политик L1/L3

Рабочий прототип читает YAML и принимает синтетические события. Сам движок возвращает решение и ID правила. L1-конвейер связывает проверенный вход с метками конкретного запроса L3. Для дополнительной детекции подключён адаптированный Apache-2.0 клиент контракта NeMo Guardrails POST {prompt} -> {jailbreak: bool}; он принимает только loopback endpoint и не скачивает модель. Проверочный LangGraph-стенд выполняет настоящий путь L1 → детерминированный планировщик → L3 → ToolNode/END, HITL и кооперативную остановку, используя только безвредные лабораторные функции.

Повторение только в подготовленной VM

Не запускать этот код на Windows-хосте. Сначала согласовать опыт, проверить изоляцию гостя и зависимости ниже. Наличие AGT/Bun/OPA в VM не подтверждает наличие Python/LangGraph/Node для этого прототипа. Команды и гостевой путь фиксируются в отдельном протоколе перед повтором.

Сохранённый результат от 25.09.2026 — 84 Python + 16 Node-тестов; новых прогонов при актуализации документации не было. AGT-пилот 29.09 — отдельный опыт оригиналов, его результаты не засчитываются прототипу.

demo.py выводит JSON с решениями. verify.py повторяет тесты Python и Node-адаптера, сохраняет рядом test-results.json, test-results.txt и adapter-test-results.tap. Если в текущем Python установлен LangGraph, он также запускает реальные runtime-тесты; версия записывается в отчёт. Конфигурация находится на уровень выше: Политики_L1_L3_v0.1.yaml. Требуются Python 3.10+, PyYAML, langgraph==1.2.12 для runtime-тестов и Node для тестов DSH-адаптера. Требования самого DSH выше; его зависимости не устанавливались.

Как менять настройки

  • controls.rate_limit: disabled: шестое чтение станет разрешённым; во включённом режиме действует лимит пяти чтений за 60 секунд.
  • controls.budget_guard: disabled: отключает накопительный лимит числа вызовов/времени сеанса; оконный rate limit продолжает действовать отдельно.
  • controls.data_flow: disabled: защищённый вызов закрывается, а не становится разрешённым. Допуски получателей и решётка задаются в data_flow.
  • controls.egress_allowlist: disabled: сетевые операции закрываются. Разрешённые тестовые домены задаются отдельно для каждого сетевого инструмента.
  • controls.memory_boundary: disabled: операции памяти закрываются. Во включённом режиме ключ должен находиться в namespace задачи из memory.permissions.
  • controls.sandbox_mode: read-only: симулятор отклонит запись/удаление. workspace-write разрешает рассмотреть их дальше по правилам.
  • rules[0].effect.detect_prompt_injection: false: исчезает эвристическая метка подозрения; внешний текст сохраняет untrusted.
  • Изменение tool_permissions меняет набор допустимых сочетаний задачи, инструмента и операции.
  • Выключение human_approval запрещает критические операции. Выключение L3 или обязательных проверок прав/границ приводит к отказу защищённых запросов.
  • Выключение session_stop закрывает все новые запросы: обязательный канал остановки нельзя превратить в обход. Доверенный stop_session(session_id) запрещает новые решения этого сеанса и аннулирует ожидающие/выданные подтверждения.

Меняйте YAML до нового запуска: движок делает копию конфигурации и фиксирует её SHA-256. Неизвестные поля, повторные YAML-ключи, неподдерживаемые режимы и несогласованные правила останавливают загрузку. Версии заданы строками. Восемь ID правил имеют фиксированный смысл: это ограниченный язык деклараций 0.4, а не движок произвольных выражений. Суффикс v0.1 в имени YAML пока исторический; исполняемую версию определяют поля внутри файла и хеш профиля.

Решения и подтверждения

Сначала проверяются структура запроса, права и путь; затем лимит; затем критичность операции. Запрет имеет приоритет над запросом подтверждения. Обычная разрешённая операция получает allow.

Для опасной операции сначала получается require_review и временный ID ожидающего запроса. Метод approve имитирует отдельный административный канал. Его нельзя предоставлять модели. Полученный токен действует один раз, максимум 60 секунд от запроса, и связан с полным событием и хешем политики. Одинаковый незавершённый запрос переиспользует pending ID; число pending/grant на сеанс ограничено approval.max_outstanding_per_session, просроченные записи очищаются. approved: true во входном событии не принимается. В демонстрации операторское подтверждение имитируется программно — интерфейс человека ещё предстоит реализовать.

Оконный лимит и накопительный бюджет считают выданные разрешения, а не все попытки или фактические запуски. Повторное разрешение того же session_id/call_id блокируется. Бюджет реализует доступные самому шлюзу счётчики tool_call_count и elapsed_seconds; токены и стоимость не объявлены проверенными, пока ядро не предоставит доверенные показатели. Состояние счётчиков и токенов хранится в памяти одного процесса; перезапуск его сбрасывает. Для рабочего агента потребуются синхронизация параллельных запросов и доверенный жизненный цикл состояния; конкретное долговечное хранилище планом пока не выбиралось.

L1 и границы доказанного

L1 помечает внешние источники и ищет несколько фраз вроде «игнорируй предыдущие инструкции». Это демонстрационная эвристика с ложными срабатываниями и пропусками. Дополнительно l1/nemo_jailbreak.py реализует локальный NeMo-совместимый detector client; без отдельно запущенного классификатора он не вызывается автоматически. L1Pipeline хранит результат проверки и сам добавляет source_event_ids/data_labels в событие L3. Модель не может назначить эти поля себе. Неизвестная или отсутствующая связь маркируется unknown и untrusted. L3 отдельно применяет лабораторную классификацию public/protected: отсутствие class:* консервативно считается protected, поэтому такой поток нельзя отправить в public-приёмник.

Происхождение L3-модулей

third_party/agt/approval.rego и budgets.rego — сокращённые адаптации готовых MIT-модулей Microsoft AGT из предоставленного agent-control-standard-integration.zip. Лицензия и точные пути источников сохранены в third_party/AGT_POLICY_NOTICE.md. Исполняемый адаптер l3/agt_controls.py переносит ограниченную семантику approval/budget, а также egress/IFC из соседних модулей. Прототип не использует OPA как runtime. Отдельно в гостевой VM пилота запускался OPA 1.21.0 с оригинальными политиками; это не подключение Rego к этому прототипу.

Engine.stop_session() основан на требовании N04 и сверке со штатной моделью отмены DSH: Agent.cancel({ kind: 'user' }) очищает очередь и передаёт отмену активному turn, а инструменты получают обязательный AbortSignal. Шлюз пока лишь перестаёт выдавать разрешения и очищает HITL-состояние. Реальный DSH-адаптер должен дополнительно вызвать Agent.cancel и дождаться whenIdle(); иначе нельзя утверждать, что уже начатый эффект остановлен.

Адаптация NeMo описана в third_party/NEMO_GUARDRAILS_NOTICE.md. Тяжёлый upstream-вариант с Torch, Transformers и GPT-2 Large не переносился и не запускался.

Проверка путей разрешает существующие ссылки и запрещает выход из workspace, включая чтение. Проверка и фактическое открытие файла не атомарны: тест не доказывает защиту от подмены пути между ними. sandbox_mode здесь влияет на решение; процесс ОС в песочницу не помещается. Настоящее ограничение ресурсов выполняется отдельно через DSH/ОС/VM.

Поля личности, задачи, имени инструмента и операции в стенде задаёт доверенный тестовый код. Реальный адаптер обязан получать их из контекста сеанса и реестра инструментов, иначе агент сможет подменить полномочия. Сам процесс симулятора и его конфигурация не защищены от другого кода под той же учётной записью.

Проверка

Тесты покрывают разрешённое чтение, права по задаче, неизвестные инструменты, traversal/ссылки/соседний каталог, лимиты и переключатели, одноразовое подтверждение, изменённые аргументы, просрочку, отсутствие канала подтверждения, поддельное поле одобрения, неверные конфигурации и безопасный состав записи журнала. Сценарии не читают пользовательские файлы: временные файловые объекты создаются только для проверки разрешения путей.

audit_record и отчёт не сохраняют текст входа, аргументы, путь или токены подтверждения. Это экспорт тестовых решений, не защищённый эксплуатационный журнал. Никакие тесты здесь не подтверждают безопасность DSH или отсутствие вредоносного кода в его зависимостях.

Следующее подключение

Основная точка DSH — tools/pre-execute и финальная tools.guard() в packages/core/tools/src/index.ts. В dsh-adapter реализованы сопоставления для read/write/edit, контекст сеанса, обмен с постоянным Python-процессом и передача HITL через approval.request. Пройдены контрактные тесты с имитацией ToolRuntime; установка и запуск DSH пока не выполнялись. Эти направления прежнего прототипа не являются текущим разрешением на разработку. Текущий приоритет — аудит и испытания оригиналов по основному плану; UI/ConfigEditor не добавлять без отдельного поручения.

LangGraph runtime spike

langgraph_adapter/adapter.py принимает форму tool call LangGraph (id, name, args, необязательный type=tool_call) и преобразует её в общий tool.requested. Сейчас сопоставлены лабораторные файловые вызовы, http_request → network.http/network.send и заведомо запрещённый modify_policy → file.write/policy.modify. Доверенный хост заранее связывает thread_id с actor_id и task_id; поля внутри аргументов модели не меняют полномочия. runtime.py содержит два графа: прежний контрактный policy → ToolNode и проверочный сквозной input/L1 → planner → policy/L3 → ToolNode → result/L1. Во втором варианте только L1 назначает source_event_ids и метки; планировщик не может подменить provenance через аргументы инструмента. Вывод инструмента повторно рассматривается как недоверенный вход с origin: tool; слишком большой результат заменяется безопасным сообщением до возврата из графа, но это не отменяет уже совершённый инструментом эффект.

Контрактные тесты проверяют разрешение, запрет выхода из workspace, неизвестный инструмент, незарегистрированный thread, неизменяемость контекста, require_review, одноразовый resume, изменение аргументов и отсутствие канала подтверждения. Runtime-тесты на официальном пакете LangGraph 1.2.12 дополнительно подтверждают: разрешённый вызов достигает настоящего ToolNode один раз; запрещённый не достигает; удаление останавливается через interrupt() и выполняется только после корректного Command(resume=...); отказ и неверный ответ закрываются; пакет tool calls блокируется. Сквозные тесты дополнительно проводят настоящий вход через L1, проверяют перенос меток в L3, запрет подделки provenance, неизвестный tool, неизменность HITL-вызова, повтор call ID, IFC для защищённых данных, доменный egress allowlist, rate и cumulative budget одного сеанса, fail-closed при исключении policy hook, запрет policy.modify, остановку до dispatch и отмену уже запущенного кооперативного инструмента.

langgraph_adapter/cancellation.py подключается как ToolNode.wrap_tool_call. Доверенный stop_session() одновременно закрывает новые решения движка и выставляет сигнал активному инструменту. Инструмент должен периодически вызывать cancellation_point(). При отмене после запуска возвращается effect: may_have_occurred; это намеренно не выдаётся за откат уже совершённого эффекта. Некооперативный или зависший инструмент данный Python-механизм принудительно не завершает — для такой гарантии нужен отдельный процесс/контейнер/VM на приостановленном этапе 5.

Используется InMemorySaver, не долговечное хранилище. Детерминированный planner в тестах не является LLM. Реальные файловые/сетевые эффекты, DSH и изоляция ОС не запускались.
