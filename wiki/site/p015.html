Этап 5.2 — подготовка изолированной среды

Статус: приостановлено пользователем 24.09.2026. Способ размещения и гостевая ОС не выбраны. Скрипт ниже — неутверждённый черновик. Не создавать и не запускать VM, не загружать образ и не устанавливать среду до отдельного указания. Сначала требуется обсудить и проверить подход.

Проверено на хосте 24.09.2026

  • Windows 11, VirtualBox 7.2.18 установлен в D:\Virtual machine.
  • Зарегистрированы четыре пользовательские VM (Kali и три другие); запущенных VM на момент проверки нет.
  • 12 логических процессоров, аппаратная виртуализация поддерживается; всего около 15.3 ГБ RAM, свободно около 2.7 ГБ на момент проверки.
  • На D: свободно около 431.6 ГБ. В корне D:, непосредственно в Downloads и D:\ЗАГРУЗКИ ISO не обнаружены. Это не полный поиск всех дисков.
  • Системный Node 22.14.0. Локальный DSH требует ^22.19.0 || >=24.0.0, pnpm 11.7.0 (источник: package.json DSH).

Подготовленный профиль

New-LabVM.ps1 формирует отдельную VM в D:\AI-Agent-Security-Lab\vms. Профиль: 2 vCPU, 4096 МБ RAM, динамический диск 48 ГБ для Linux или 64 ГБ для Windows 11; сеть, shared clipboard, drag-and-drop, USB и VRDE отключены. Общие папки не добавляются. VM создаётся выключенной, без установочного образа. Существующая VM или каталог с тем же именем приводят к отказу.

Просмотр плана без изменений:

& D:\AI-Agent-Security-Lab\environment\New-LabVM.ps1 -Guest Linux

Флаг -Create выполняет создание выбранной VM, но не запускает её. Пока выполнен только просмотр Linux-профиля; гостевая ОС пользователем не выбрана. Windows-профиль не проверен запуском.

Последовательность продолжения

  1. Выбрать гостевую ОС: Linux для первого стенда или Windows 11 для исследования именно Windows-изоляции. Существующие VM не используются как шаблоны без отдельного решения владельца.
  2. Получить официальный установочный образ и проверить его контрольную сумму. Для Windows требуется решить вопрос лицензии/оценочного образа. Подлинность образа и источник фиксируются в реестре.
  3. Создать отдельную VM и перед запуском освободить память хоста: желательно не менее 6 ГБ доступной памяти для гостя с 4 ГБ.
  4. Установить гостевую ОС, создать отдельного пользователя лаборатории. Доступ к личным файлам хоста не предоставлять.
  5. Для получения пакетов спроектировать отдельный режим снабжения. NAT сам по себе не запрещает доступ к локальной сети; нельзя считать его сетевой изоляцией. Рабочий профиль по умолчанию остаётся без сети.
  6. Установить совместимый Node 24.x, pnpm версии из package.json, Python/PyYAML внутри гостя; версии и источники зафиксировать. Передать только исходники стенда и DSH через одноразовый носитель/контролируемый канал.
  7. Сделать снимок чистой среды, собрать DSH, проверить ограниченный набор инструментов и интеграцию этапа 5.3. API-ключи и подключение модели для проверки отказа инструмента не требуются.
