Этап 5.1: адаптер контракта DSH

adapter.mjs реализует регистрацию проверки через ctx.on('tools/pre-execute', ...) и финального запрета через ctx.tools.guard(...). Это библиотека адаптера, не устанавливаемый Cordis-плагин. Подключение к реальному DSH и упаковка — этап 5.3; страница настроек — этап 6.

bridge.mjs запускает один процесс worker.py через стандартные потоки, без shell и сетевого порта. Python хранит лимиты и одноразовые одобрения на протяжении жизни процесса. Потеря связи или тайм-аут закрывают мост; автоматического перезапуска со сбросом лимитов нет. Для смены профиля требуется управляемый новый экземпляр; горячая смена в этой версии отсутствует.

Подключение на уровне контракта

Доверенный код хоста создаёт PolicyBridge, передаёт его в bindPolicyGate и регистрирует сеанс через enroll(session, { actorId, taskId }). Идентичность пользователя и права задачи приходят из хоста. Метод регистрации и метод выдачи подтверждения нельзя предоставлять как инструменты модели.

Поддержаны реальные имена файловых инструментов DSH: read, write, edit, аргумент file_path. Они преобразуются в file.read/read и file.write/write. Принимаются абсолютные локальные пути; shell, относительные пути, удалённая FS, read_image, MCP и остальные инструменты пока отклоняются. Это намеренно ограниченный набор для первого эксперимента; общий агент с ним пока не получится.

Исходные аргументы целиком входят в отпечаток запроса. Агент не может передать другой task_id через аргументы и получить новые права. Менять сопоставления инструмента с операцией может только разработчик доверенного адаптера.

Порядок решения

  1. Проверка зарегистрированного контекста сеанса и преобразование запроса.
  2. Другие обработчики pre-execute сохраняют право отказа или запроса подтверждения.
  3. Python принимает решение. Для require_review вызывается ctx.approval.request с агентом, именем инструмента, callId и сигналом отмены. Только allowed-once позволяет продолжить.
  4. Адаптер сравнивает аргументы после подтверждения, получает одноразовое разрешение Python и повторяет проверку.
  5. Финальный guard допускает только этот проверенный объект исполнения с тем же контекстом и аргументами. Если другой обработчик обошёл pre-execute или изменил аргументы, guard запрещает исполнение.

Guard не может защититься от доверенного кода, который отключил сам плагин или вызвал ОС вне ToolRuntime. Владение конфигурацией и ограничения ОС остаются отдельными этапами. После close() guard остаётся в режиме отказа; disposeAfterRuntimeStopped() разрешён только при остановленном исполнителе.

Что проверено

16 тестов запускают настоящий локальный Python-движок и имитируют контракт Cordis/DSH. Они считают вызовы безопасного тестового тела инструмента. Подтверждены разрешённый вызов, отказ неизвестному инструменту и пути, обход предобработчика, подмена аргументов, неподтверждённый сеанс, общий лимит параллельных запросов, одноразовое одобрение, отказ/неверное одобрение, изменение содержимого, тайм-аут HITL, остановка движка, неверная конфигурация, отмена, закрытие адаптера, независимый отказ другого обработчика и изменение контекста.

Запуск:

node --test D:\AI-Agent-Security-Lab\policy-gateway\dsh-adapter\adapter.test.mjs
python D:\AI-Agent-Security-Lab\policy-gateway\verify.py

Второй вариант повторяет 26 тестов движка и 16 тестов адаптера, сохраняет общий JSON и adapter-test-results.tap. Тестовая имитация не доказывает совместимость с настоящим ToolRuntime: это отдельный критерий этапа 5.3. Зависимости и скрипты DSH не запускались.

Происхождение API

Локальный DSH 0.1.7-rc.1, архив SHA-256 7DDDFDB7A5E25001394B895A9EEA743C89DF9238BB0093EFF34CB5ABD1C4417E:

  • packages/core/tools/src/index.ts: события pre-execute, финальный guard, ToolExecutionInput.
  • packages/fs/tool-fs/src/read.ts, write.ts, edit.ts: имена инструментов и аргумент file_path.
  • packages/fs/tool-fs/src/session-cwd.ts: cwd из session.header.
  • docs/subsystems/approval.md: callId, allowed-once и прочие ответы.

Исходный код DSH не скопирован: адаптер написан для проекта на основе этих контрактов. Для этапа 6 использованы docs/cookbook/adding-a-settings-card.md и packages/settings/settings/README.md: Config/volatile + ConfigEditor, отдельная клиентская страница, проверка ревизий.
