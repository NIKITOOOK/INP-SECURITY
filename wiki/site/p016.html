A3 — подготовка ЛР №0: среда для пилота AGT budgets

Статус: методичка подготовлена, ЛР №0 пользователем не выполнена. Дата замера хоста: 27.09.2026, около 05:12 UTC. Пользователь управляет VirtualBox/гостем самостоятельно; агент не создавал, не запускал и не менял VM, сеть, ACL или пакеты хоста. Пользователь уточнил: Ubuntu есть только в WSL, отдельной Ubuntu VM нет; для ЛР выбрана новая отдельная Ubuntu Server VM. Существующие Kali/Astra/Windows 10 VM и WSL не используются как стенд этой ЛР.

Зачем нужна среда

Для ЛР №1 надо проверить оригинальный budgets.rego и его тест в OPA без LLM, сохранив результат, версию бинарника и настройки изоляции. В ЧТЗ это относится к локальному испытанию политики, а не к доказательству безопасности всего агента. Проверка Rego verdict не проверяет блокировку настоящего инструмента.

Предлагается образ Ubuntu Server 24.04.5 LTS amd64 с официальной страницы Canonical. Пользователь сообщил об Ubuntu только в WSL, Docker-сетях и VM Kali/Astra/Windows 10. Ни одна из них автоматически не становится стендом ЛР.

Проверенные внешние ориентиры

  • Oracle VirtualBox 7.2 Security Guide: default NAT не равен отключённой сети, а общие папки и clipboard создают каналы между гостем и хостом. В режиме испытаний по плану адаптеры сети выключены; shared folders, clipboard, drag-and-drop, USB, VRDE и 3D не включаются. Docker-сеть на хосте не заменяет этой проверки.
  • Oracle VirtualBox 7.2 Working with VMs: снимок фиксирует состояние VM для отката, но восстановление теряет изменения после снимка и не отменяет внешние эффекты.
  • Ubuntu Server 24.04 requirements: для amd64 предлагается 3 ГБ RAM или больше и 25 ГБ хранения или больше; профиль 4 ГБ/64 ГБ выше этих ориентиров, но требует достаточной свободной памяти на хосте. Страница загрузки Ubuntu предлагает 24.04.5 LTS как предыдущий поддерживаемый LTS.
  • OPA v1.21.0 release от 24.09.2026 и OPA install guide: для ЛР №1 предлагаем закрепить opa_linux_amd64_static версии 1.21.0 вместо latest. Страница релиза указывает SHA-256 бинарника 5eef70644868bb04d0556bcc795ee42f2ab379e73f51d1bfa30f83e1305bc9b9; пользователь сверяет фактически полученный файл с опубликованным значением и .sha256 до запуска. Документация rego.v1 объясняет необходимую совместимость. Если на релизе файл/хеш изменился или недоступен — остановиться, не подставлять другую версию молча.

Ход ЛР №0 — выполняет только пользователь

  1. ХОСТ, до создания: закрыть ненужные приложения и повторно измерить доступную память Windows и свободное место D:. Для профиля 4 ГБ гостю нужен дополнительный запас хосту; если свободная память всё ещё меньше 4 ГБ плюс запас Windows, остановиться и прислать замер. Замер 1,8 ГБ сейчас не допускает запуска опыта. Не уменьшать RAM или диск без записи изменённого профиля.
  2. ХОСТ, источники: получить официальный Server ISO 24.04.5 amd64 (имя ubuntu-24.04.5-live-server-amd64.iso, около 3,8 ГБ), а не Desktop/WSL-образ. В официальном SHA256SUMS для него опубликован SHA-256 97f3d7ffb032c3eb3b23d2c8be9cc76e60c2c1f2c0146ba5ba9fe01cafae0fd8; есть и подпись списка. После скачивания выполнить на хосте Get-FileHash -Algorithm SHA256 -LiteralPath 'ПОЛНЫЙ_ПУТЬ_К_ISO' и сравнить, при наличии проверенного ключа Canonical также проверить подпись списка. Отдельно открыть релиз OPA v1.21.0, получить opa_linux_amd64_static и его .sha256, сверить SHA-256 с указанным выше. Записать URL, дату, размеры и фактические хеши. Эти бинарники не запускать на хосте. Несовпадение — стоп.
  3. ХОСТ, VirtualBox GUI: создать новую VM типа Linux/Ubuntu 64-bit с уникальным именем, разместив VDI на D: вне дерева workspace-current; профиль 2 vCPU, 4 ГБ RAM, динамический VDI 64 ГБ, без GPU passthrough. Убедиться, что не выбрана существующая Kali/Astra/Windows VM и не указан её диск. Приложить проверенный Ubuntu ISO к виртуальному оптическому приводу. Пока сеть нужна лишь для снабжения/обновления ОС, её использование отделить от опыта и записать; в режиме испытания сетевые адаптеры должны быть выключены, NAT недостаточен.
  4. ГОСТЬ, установка: установить Ubuntu Server обычным установщиком только на новый пустой виртуальный диск. В установщике проверить выбранный диск перед подтверждением. Не добавлять реальные секреты, SSH-ключи хоста, корпоративную учётную запись и папки проекта. Записать cat /etc/os-release, uname -m после первого входа. ОС-пакеты/обновления можно снабдить до изоляции; в этот период не исполнять код исследуемых ZIP и не считать среду песочницей.
  5. ХОСТ/ГОСТЬ, OPA и комплект: обеспечить попадание проверенного opa_linux_amd64_static и минимального комплекта пилота в гостя через отдельный носитель только для чтения, например пользовательский ISO. Для его изготовления использовать только проверенный инструмент, не подключать writable shared folder проекта. Точный инструмент и команда изготовления ISO зависят от имеющихся средств и фиксируются в протоколе до переноса; если безопасного носителя нет — пауза, а не включение clipboard или общей папки. В госте скопировать файлы с носителя в отдельный каталог, повторно сравнить SHA-256 OPA и оригиналов с карточкой, затем разрешить запуск opa version и записать вывод. До проверки хеша бинарник не исполнять. При необходимости дать исполняемое право только гостевой копии OPA; оригиналы .rego не править.
  6. ХОСТ, граница опыта: выключить VM. В GUI VirtualBox установить Network: все адаптеры disabled, Shared Folders: пусто, Shared Clipboard и Drag'n'Drop: Disabled, USB controller/filters: Disabled, Remote Display/VRDE: Disabled, 3D Acceleration: Disabled. Не использовать NAT, host-only, bridged или Docker network как замену отключению адаптеров. Проверить настройки повторно перед запуском ЛР №1 и сохранить реальные снимки экранов настроек.
  7. ХОСТ/ГОСТЬ, контроль: запустить гостя только после повторного замера RAM, убедиться, что opa version показывает 1.21.0, sha256sum бинарника и Rego-файлов совпадают с карточками, а сетевая связность отсутствует. Отрицательный сетевой тест сам по себе не доказывает отсутствие всех каналов — главное доказательство здесь конфигурация отключённых адаптеров и общих функций. Затем пользователь создаёт чистый снимок VM before-agt-budgets, записывает дату и идентификатор. Снимок фиксирует гостя, не отменяет внешние эффекты.
  8. ХОСТ, завершение: пользователь заполняет протокол ниже и присылает обезличенные факты/скриншоты; никаких тестов AGT в ЛР №0 не запускать. Если настройки не удалось подтвердить или источник/хеш не сошёлся, отметить блокер. Только после принятия протокола перейти к ЛР №1.

Критерий A3: методичка есть, но переход в A4.1 разрешён лишь после фактического протокола пользователя: новая VM с проверенным гостем/OPA, отключёнными каналами и сетью, чистым снимком. Сейчас A3 в работе; VM и OPA не проверены практикой. Изоляция VirtualBox снижает риск, но не доказывает абсолютную безопасность ОС или агента.
