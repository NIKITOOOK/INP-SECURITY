## Что нужно для принятия облачной ЛР №0

1. Определить проверяемый режим опыта без исходящего интернета и публичного входа, сохранив управляемый путь доступа к гостю. Отдельно описать режим снабжения для обновлений и загрузок. Не считать отсутствие публичного IP достаточным.
2. Подготовить перенос **только** выбранного комплекта AGT budgets и OPA с проверкой SHA-256 на обеих сторонах; закрытый SSH-ключ и настоящие секреты в комплект не включать. Оригинальные файлы не редактировать.
3. Выбрать и зафиксировать чистую точку отката Azure и стоимость хранения до её создания. Откат не отменяет внешние эффекты.
4. Собрать фактический протокол: конфигурация сети, отрицательная проверка выхода в режиме опыта, версии и хеши в госте, способ доступа/отката. `opa version` и тем более тесты AGT выполнять только после отдельной фиксации принятия A3, согласно просьбе пользователя.
5. После сеанса проверить `Остановлено (освобождено)`. Если любая граница или перенос не подтверждены, отметить блокер, а не объявлять A3 завершённой.

**Следующий пакет:** A3.1–A3.2 по [уточнённой программе](../../Программа_полной_проверки_в_Azure.md): паспорт пригодности, конкретный удалённый канал, перенос/возврат логов, граница процесса и стоимость. A4.1/ЛР №1 начинается только после принятия A3.

## Уточнения проекта 28.09.2026 — ещё не факты настройки

Пользователь хочет испытывать наработки удалённо силами агента в уже созданной Azure VM. Прямой SSH с ноутбука не подтверждён: нет публичного IP, а Bastion Developer не поддерживает native file transfer. Имеющиеся Run Command/браузерный доступ нужно оценить как канал снабжения и управления с отдельным непривилегированным исполнителем; Run Command требует исходящего соединения для возврата результатов и ограничивает вывод. Эти ограничения и официальные источники приведены в программе, Q3/Q4.

Пока не проверены также полномочия managed identity, доступ процесса к metadata/платформенным адресам, полнота выгрузки логов, предел расходов и фактический откат. Ни одно из этих условий этой записью не объявляется выполненным. Во время корректировки плана облако повторно не инспектировалось.
