# Матрица настроек L3 и границ автономности

Дата: 25.09.2026. Профиль: `research-l1-l3`, schema/policy 0.4.

Эта таблица описывает фактическое поведение лабораторного Policy Gateway. Она
не является настройкой Windows/Linux и не утверждает, что реальный DSH или
LangGraph уже защищён.

## Переключатели

| Настройка | `enabled` | `disabled` | Почему так безопасно |
|---|---|---|---|
| `layers.input` | L1 валидирует и маркирует вход | Возвращает `unchecked`, но сохраняет `untrusted` | Выключенный детектор не делает ввод доверенным |
| `layers.model` | Не поддерживается схемой | Единственный допустимый режим | L2 остаётся `?`, его нельзя объявить включённым |
| `layers.system` | L3 рассматривает действие | Все действия получают `deny` | Без L3 нет исполнения |
| `tool_allowlist` | Нужна точная пара задача/инструмент/операция | Все действия получают `deny` | Нет неявного allow |
| `workspace_boundary` | Канонический путь обязан быть внутри workspace | Файловые операции получают `deny` | Выключение проверки пути не открывает весь диск |
| `rate_limit` | Работает оконный лимит | Оконный лимит не применяется | Накопительный `budget_guard` остаётся отдельным ограничением |
| `budget_guard` | Ограничивает число разрешений и время сеанса | Накопительный бюджет не применяется | Оконный rate limit и остальные gates сохраняются; использовать только для сравнительного опыта |
| `data_flow` | Проверяется no-write-down `public/protected` | Все действия получают `deny` | Нельзя выключить классификацию ради обхода |
| `egress_allowlist` | `network.send` требует допустимый домен | Сетевые действия получают `deny` | Нет сети без проверки адресата |
| `human_approval` | Критическое действие получает `require_review` | Критическое действие получает `deny` | Нет автоматического одобрения |
| `memory_boundary` | Ключ обязан входить в namespace задачи | Операции памяти получают `deny` | Право на инструмент не означает право на всю память |
| `session_stop` | `stop_session()` блокирует новые решения | Все действия получают `deny` | Канал остановки обязателен |
| `sandbox_mode` | `workspace-write` допускает рассмотрение write/delete; `read-only` запрещает их | Иного режима нет | Это решение middleware, а не ОС-песочница |

## Что означает автономность

Автономность задаётся не «смелостью модели», а пересечением четырёх условий:

1. задача явно имеет право на инструмент и операцию;
2. ресурс, путь, класс данных и адресат допустимы;
3. лимиты не исчерпаны и сеанс не остановлен;
4. операция не критическая либо человек подтвердил точные аргументы.

В текущем профиле без человека разрешены чтение/запись внутри тестового
workspace и тестовые операции памяти только для явно перечисленных задач.
Удаление и `network.send` требуют HITL. `policy.modify` запрещён всегда и не
может быть разрешён подтверждением модели или человека через этот контур.

## Кто может менять профиль

Исполняемого административного API пока нет. YAML меняется оператором вне
процесса агента и применяется только после строгой валидации при новом запуске.
Неизвестное поле, повторный YAML-ключ, ослабленный default, отсутствующий sink,
allowlist или обязательное правило прекращают загрузку; действующий процесс не
получает автоматически частично разобранную конфигурацию.

До этапа 4 запрещено заявлять горячее обновление или откат как реализованные:
создание нового `Engine` сбрасывает in-memory бюджеты, остановленные сеансы и
HITL-токены. Сначала выбранное ядро должно предоставить доверенный жизненный
цикл конфигурации и сеансов. Восстановление файла/ACL относится к этапу 5.

## Оставшиеся `?`

- реальные инструменты, задачи, роли согласующих и адресаты;
- классификация корпоративных данных вместо лабораторных `public/protected`;
- доверенный UI/API администратора и источник `actor_id`;
- перенос или сброс защитного состояния при смене версии;
- активная отмена уже запущенного действия в выбранном ядре;
- L2 и фактическая изоляция ОС.
